## 解析と保存の境界

`jtd::inspect` は、対応する `DocumentText` の論理 UTF-16 unit、piece と物理範囲、
レコード、書式範囲、診断を返す。未知のクラスも論理上の範囲として検査できるが、
認識した内容だけを `jtd::read` が表示モデルに変換する。検査結果を元に JTD を
書き戻す機能ではなく、未知データを残した JTD の編集・再保存は未対応である。

| 対象 | 現状 | 未解決 |
| --- | --- | --- |
| ブロック・本文・書式イベント | `TextV.01` / `QLSTV.01` の観測形を境界検査し、断片を論理順に結合する。未知の書式末尾と診断を検査結果に残す。 | 未知のプロパティや末尾値の意味、他のバージョン・暗号化形式、保存時の未知領域の保持。 |
| 行ヘッダー `0010` | TLV の `008f` を罫線表示行として読み、明示的な `0024` の既知の揃え値などを解釈する。 | 記録されていない設定の継承や、未解釈の段落属性・配置指定。 |
| 区画 `0030` と行末 `000e` | `left` / `right` の宣言を表示行のグリッドと余白へ近似し、罫線や区画を保持する。 | 区画フラグの継続・終端・結合の意味と、Word の論理表との完全な対応。 |
| 通常レコード `0000` | `inspect` ではクラスと payload の unit 範囲を取得できる。表示への意味付けはしていない。 | フィールドの意味、後続インラインとの関係、文字配置との因果関係。下記の一例だけで決めない。 |
| 文字・ルビ・フォント | 対応する文字書式とルビ、既定書体参照の一部を表示モデルに写す。 | インライン書体選択子、縦横倍率、ルビの詳細配置や環境ごとの代替書体。 |
| 複数シート・埋め込み | 検出できた追加シートと埋め込み関連領域を通知し、画像候補を位置未確定の一覧として検査できる。 | シートの順序・設定と本文取り込み、画像のページ・座標・描画順。検出数は未対応内容の網羅数ではない。 |
| JTT / JTTC | 無圧縮 JTT と、観測された LH5 圧縮 JTTC の部分集合を扱う。 | 他の圧縮・旧形式、画像主体文書の原位置での再現。 |

`DocumentViewStyles/100d` では、既知の行数に後続する 4 byte の意味は未確定だが、
行数自体は保持する。`QLSTV.01` の末尾にある場合の 4 byte も意味未確定で、
両者を同じフィールドとみなさない。検査 API の詳細と制限は[形式調査](jtd-format-notes.md)を参照。

## 縦書き見出しの配置

**観測。** 対応する一太郎出力 PDF のあるローカル縦書き文書 1 件では、出力と
参照はともに 9 ページだった。2 ページ目の見出しセルでは、参照で文字がセル内に
間隔を置いて配置されるのに対し、ibisOffice の出力では先頭側に寄る。ページ数や
一部の目視比較は、全ページの一致を示さない。

**現在の読み。** 対象の見出しを含む罫線行の `0010` に観測された TLV は `008f` で、
既知の揃えを示す `0024` はなかった。現アダプターは、縦書き罫線行の明示的な
揃えがない場合に前段落の揃えを継承せず、左揃えを設定する。これは既知の誤継承を
避ける方針であり、原本で均等配置が指定されていないことの証明ではない。

**未確定の観測。** 同じ行では `0030` の区画宣言に続き、`0000` の payload として
16-bit unit 列 `[0, 7, 220, 525, 0]` が観測され、その後に `[0, 3]` のインライン
文字列が続いた。この payload は複数の隣接する区画でも見られた。列の単位や意味、
区画・インラインとの関係は分からず、見出しの均等配置を指定していると断定できない。
この `0000` は通常レコードのクラス名であり、インラインの selector `[0, 3]` とは別である。

次の検証では、一太郎で揃えだけを変更した対照文書と各 PDF を作成し、論理 unit・
書式イベント・区画・描画位置を比較する。既存の文字列だけを条件に中央や均等配置を
推測しない。現在の環境ではその一太郎での対照作成・再読込は確認していない。

## 縦書き表と Word の保存

JTD の `FlowRowLine` は表示上の行内線分であり、現在の DOCX 書き出しでは失われる。
`tbRl` セクションを指定するだけでは、Word for Mac で検証した表は JTD と同じ
縦書き表の配置にならなかった。表示行を右から左に DOCX 列、元のグリッド区間を
上から下に DOCX 行へ転置する試作は単一ページの合成表で試したが、共通グリッド、
結合、前後の段落と複数ページの分割を扱う実装はまだない。

合成 DOCX の Word for Mac での限定観測は次のとおり。他バージョンや編集後の
再配置に一般化しない。

- セルの `tbRlV` では日本語が正立し、`tbRl` では回転した。セルの値の読み書きと
  描画の区別はフォークへ統合済み。セクションの `tbRl` とは意味を分ける。
- 縦結合セルの外周は開始セルと継続セルで別の罫線を指定すると、一部分だけに
  表示できた。一方、結合セルの内部を横切る辺罫線は表示されなかった。
- 固定高さの結合セル内に浮動線図形を置けたが、縦書きセルでは横書きと同じ
  アンカーが隣のセルへずれた。合成例ではセル幅分の横オフセットで戻せたものの、
  罫線との小さなずれが残り、ページ分割・編集・余白を変えた場合は未検証である。

新規 DOCX 表の `vMerge` 保存はフォークに統合済みで、上流への提案は
[ibisjp/ibis-office#222](https://github.com/ibisjp/ibis-office/issues/222)、
その差分レビューは[フォークの PR #71](https://github.com/masanork/ibis-office/pull/71)。
これは部分線分の DOCX 出力や縦書き表の転置の完成を意味しない。
