# 構造化データのプレビュー

デスクトップ版の「開く」から、UTF-8 の JSON／XML、SD-JWT の
コンパクト形式、mdoc の単一文書（CBOR またはテキスト表現）を読み取れます。
項目名と値を並べ、元の位置をパスで表示します。文字列と数値を見分けられるよう、
JSON の文字列は引用符で囲み、数値は元の精度で表示します。
既存の法令 XML や FHIR の専用ビューが該当する場合は、そちらが優先されます。

プレビュー中は編集や保存を行いません。XML の DTD は読み込まず、
内容をリンクやスクリプトとして解釈しません。最大 1 MiB、1,000 項目、
32 段の階層までを対象とし、長い値は省略記号付きで表示します。

## 修了記録で試す

[test/fixtures/structured-preview](../test/fixtures/structured-preview) の
`training.json`、`training.xml`、`training.sd-jwt`、`training.mdoc`
を順に開いてください。全て架空の記録です。

- どのファイルにも研修名と修了日があります。
- JSON と XML では管理番号 `00123` も読めます。Wallet の提示サンプルには
  管理番号が開示されていません。提示だけから、元の資格情報に管理番号が
  存在するかは判断できません。
- 資格情報のプレビューが表示する照合件数は、ファイル内の開示データと
  ダイジェストとの一致数です。署名、発行元の信頼性、保有者や端末への
  結び付けを確認したという意味ではありません。

サンプルはテスト用の鍵で生成しています。再生成する場合は
`cargo run --locked -p ibis-formats --example structured_preview_samples -- <出力先>`
を実行してください。

## 次に確認すること

upstream への提案前に、Wallet の実装を知らない利用者にこの記録を開いてもらい、
「何を受け取ったか」「何が提示に含まれないか」「何が未検証か」が
表示だけで分かるか確認します。提案の中心は、構造化ファイルを文書編集や
外部サービスへの送信を伴わず閲覧できることです。

フォームへの事前入力は、確認画面で転記元の項目、転記先の欄、変更前後を
確認できる設計から始めます。まず名前付きセルを持つ Excel を対象にし、
その後に入力欄付き PDF と、利用者の同意を経た Wallet 連携を検討します。
