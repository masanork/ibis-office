# 一太郎対応の方針と残課題

2026-11-11 時点。JTDの対応範囲は [プレビュー](jtd-preview.md)、検証の範囲は
[構造化インポート](jtd-structured-import.md)と[表示互換性](jtd-layout-compatibility.md)を参照。

## 保存形式の判断

既存のWord 97–2003 `.doc` は読み込み時にDOCXに変換し、デスクトップでは新しい
`.docx` として編集・保存する。`.xls` は変換して編集し `.xls` にも書き出せる一方、
`.ppt` の通常の保存ダイアログは `.pptx` 等を提供する。バイナリ形式に一律の往復保存
方針があるわけではない。JTDはまず認識できた内容をDOCXとして編集可能にし、元のJTDは
保持する。変換では画像・未対応の書式・一部の罫線などが失われる。

[EZPZ File JTD](https://github.com/ezpzfile/ezpzfile-jtd/tree/fe42d44d341f993ae27aa83d3864fba58bb2badc)
は原本を修正するJTD保存を実装し、一太郎でのテスト結果を報告している。直接移植は
保存経路・モデル・ライセンス表示の整理に加え、未知データや多様なバージョンについて
別途検証を要する。保存機能だけでも、限定された編集対象の調査・統合・合成試験に
数週間、実文書と一太郎各版の受け入れ試験を含めるとさらに数週間以上を見込む概算で、
実サンプルと検証環境の確保によって大きく変動する。現段階では見積もりの不確実性が高い。
一太郎へ戻す実需と検証環境が得られた時点で再評価する。

## 優先する改善

1. 欠落を明示する。複数シート、埋め込み、未知の書式・図形、変換不能な罫線を検出し、
   認識できたものと未対応なものを利用者に伝える。
2. 複数シートを独立して読み、順序・ページ設定を検証したうえでDOCXに出す。
   EZPZの `ObjectSheets/DocSheet` 探索を手掛かりとする。
3. 画面の部分罫線をDOCXに保持し、セル結合・文字配置・改ページ・縦書きの残差を
   一太郎生成の対照PDFと比較する。
4. JTT/JTTC、ヘッダー・フッター・脚注、画像・図形、フィールドを実例ごとに対応する。
   JTTCは [OpenJTD](https://github.com/OpenJTD/rjtd/tree/cfb44c9ac53126e00808c49709fb4dade8a4daae)
   の観測した圧縮ストリームを参考にし、展開上限と不正入力の試験を伴わせる。
5. 対象とする一太郎の版・機能を定め、権利のある文書と対応PDFで本文、表、画像、
   ページ分割、描画残差を検証する。合成fixtureは回帰試験に使うが実機互換の証拠とはしない。

「完全に近い」の判断は、対象版と機能を明示したコーパスで個別に行う。現在の22文書の
本文等の照合は、文書全体の再現やWord・一太郎実機での一致を意味しない。
