# シートの異体字照合: 上流向け調査（作業中）

## 対象と境界

表示・編集時の PUP 対応は [#158](https://github.com/ibisjp/ibis-office/issues/158) に関連し、ここで扱う照合とは独立する。選択したシートの文字列を比べ、表記の異なる候補とセル位置を示す。セル値を変更せず、同じクラスタでも同一人物・同一住所・置換可能性の証拠とはしない。

`acf210d` で統合ブランチ（現 `sorane`）に入ったローカル試作は、実行時に gjs や soroe を参照しない。`IBIS_VARIANT_BITMAP` をビルド時に指定した場合のみ辞書が入り、指定しなければ辞書なし。辞書の生成元のライセンス確認が終わるまで配布用には使わない。PUP の試作ブランチはこの機能に別の表示試作を重ねており、これをそのまま上流向けの独立差分としない。

## 辞書と意味

2026-11-16 のローカル実験に使用した `clusters_direct.csv` は 34,509 文字・9,538 クラスタ、SHA-256 `cf38af4da41ca5daa49d8e556d3e27ed94c9074e6b14d23ca6c67bc8dfef1293`。試作の bitmap は 171,059 bytes（zstd）、表示機能用の逆引きを含む。測定値は固定スナップショットによるもので、Web 初回通信・起動・メモリ・大きいシートでの性能を意味しない。

同スナップショットでは「髙」と「高」に加え「坂」と「阪」、「崎」と「埼」も同一クラスタに入る。これは確認候補の例で、どの文脈でも交換できるという意味ではない。クラスタは一対一の直接関係ではなく、照合画面には根拠となる辺の種類・出典も今は表示できない。候補の対象を調整できるようにするかは別途検討する。IVS を含む文字列は現試作では照合から除外し、その件数を示す。

gjs の調製者 Masanori Kusunoki からクラスタマップの使用は許諾されている。一方、元データ自体の版・加工と条件の確認が必要。`manifest.json` の記録によると、この CSV は既存 gjs DB から出力したローカルスナップショットであり、現存する `v2n_annotated_jp.csv` がその DB の入力だったことや、全入力のバージョンは証明されていない。`cluster_meta_direct.csv` の `sources` は行政系の所属タグで、関係の出典を示すものではない。

観測時の gjs `9173a4d90addf8b6c7e3563473c9195e3acbdb5e` の `export_clusters_csv.ts` は、`compat`、`v2n`、`traditional`、`simplified`、`z_variant`、`mj_substitution`、`gj_substitution`、`semantic` の関係を入力に、seeded Kruskal で direct クラスタを再計算する。ソース中の「1-hop」とするコメントと実装上のクラスタ生成の説明には差があり、実際の関係を検証せずに「直接対応のみ」と説明しない。個別エッジへの寄与、入力版、適用規約の追跡が次の作業。

コードとデータの利用条件は分けて確認する。[MJ 縮退マップ](https://moji.or.jp/mojikiban/map/) 等の条件を、利用した具体的なファイルと加工・配布形態ごとに確認する。AGPL と商用ライセンスの両方で配布できることを、コードの独自実装やクレジットから推定しない。

## 限定検証と残作業

- テスト `cargo test -p ibis-office-xlsx variant_ --lib` の照合関連 4 件は、文字列のグループ化・非変更・上限等の基本動作を確認。代表的な実データと人が確認した正解集合による精度評価ではない。
- 文字列セルだけが対象。元文字列の大小文字・空白・仮名・記号・日付・住所を正規化しない。1 セル 4,096 文字、合計 100 万文字、10 万セル、200 グループなどの制限があり、省略を表示する。
- 照合エンジンと UI の証明に必要な合成の小辞書と合成シートを用意し、誤検出・見落とし・IVS 除外・上限・辞書破損・非破壊を試す。実利用向けデータの採用は別の判断とする。
- 可能なら DB を入力から再現し、各クラスタ辺のデータソースと版、加工順序、規約を記録する。フォントが不足する候補の表示も PUP issue と連携する。
- 同じクラスタ所属を確認候補とする現方式の許容範囲、表記ごとのセルへの移動・絞り込み、大規模な選択範囲の応答性を検討する。

## 新規 issue 下書き（未投稿）

**xlsx: 選択範囲から異体字による表記揺れの候補を確認したい**

表計算で選択した範囲の文字列から、異体字を含む表記揺れの候補を一覧で確認できると、一覧データの点検に役立ちます。例えば「高橋」と「髙橋」を候補として示し、元の表記とセル位置を確認できる機能を提案します。

候補は読み取り専用とし、元のセルを自動で変更しません。一致候補は同一人物や置換の安全性を意味しないことを明示します。IVS、辞書にない文字、確認対象が多い場合の省略と、表示できない字形の扱いも検討したいです。

ローカルでは選択範囲を文字単位のクラスタで照合する試作を確認しています。辞書については元データの出典・版・配布条件とクラスタの意味を調査中で、採用するデータや実装方式は未確定です。文字の表示・編集は #158 と関連しますが、本提案は文字列の候補確認を対象としています。
