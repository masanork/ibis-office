# CSV / TSV の同一ファイル保存（試作）

元の CSV / TSV の通常保存は、読込時または直前の保存時のバイト列を基準にし、追跡した編集セルだけを置き換える。未編集のフィールド、引用、行ごとの列数、末尾の空欄や改行は再符号化せず元のバイトを保持する。これにより未編集の `00123` や、同じ文字を表す異なる CP932 の符号も保持できる。別名への CSV 出力は従来どおり UTF-8 BOM とし、以後の通常保存ではそのバイト列を基準にする。PDF / OOXML 出力には CSV の文字コードを使わない。

UTF-8（BOM の有無）、UTF-16 LE/BE（BOM 付き）と CP932 を扱う。入力が ASCII のみ、または UTF-8 と CP932 の双方として有効な場合、ネイティブ版では開く際に文字コードを選び、その選択で読み直す。選択中にサイズ・更新時刻が変わった場合は読み込みを中止する。選択肢の Shift_JIS は CP932 であり、厳密な Shift_JIS や独自外字の選択は未対応。選択処理を通らない経路では、判別できない文字コードへの非 ASCII の書き戻しを拒否する。

編集追跡は成功したセル変更の座標を記録する。行・列操作、未対応のコマンド、undo / redo、直接モデル変更があると無効になり、通常保存を拒否する。ただし追跡可能なセル編集だけを最後に保存した状態まで取り消した場合は、追跡を復帰する。未対応の操作や直接変更があった場合は、取り消しても復帰しない。既存フィールド外の編集、数式、再読込して元の値に戻らない値、CP932 に正確に表現できない文字も拒否する。内部的な undo を伴う編集も拒否されることがある。同一ファイルへのコピー・書き出しは通常保存を使うよう拒否する。大きな CSV の読込中は、不完全な内容を出力しないよう保存・コピー・書き出し・印刷を拒否する。

保存前に現在のファイルと元バイトを比較し、排他的に作った一時ファイルへ書き込んだ後、置換直前にも再比較する。失敗した場合は追跡や基準バイトを更新しない。シンボリックリンクと、Unix ではハードリンクのある元ファイルは拒否する。ただし直前の比較と rename の間には競合があり、この方式はファイルシステムの compare-and-swap ではない。保存先のパーミッションは引き継ぐが、ACL や拡張属性の保持は未検証。

macOS の合成データで、実画面から CP932 の CSV を２回編集・保存し、未編集の `00123`、末尾空欄、CRLF と元の文字コードをバイト単位で確認した。アプリのシナリオでも外部変更と表現不能文字の拒否、別名 UTF-8 保存、保存前の状態への undo と、読込中状態を模した出力拒否を確認した。実際の巨大 CSV の読込中に出力する検証ではない。このシナリオは、既存の無関係なテストにある PDF 分岐漏れ 10 件を一時的に補って実行し、実行後に元へ戻している。小さなスタックからの自動判定 CSV 読込、外部変更時とリンク時の書き込み拒否も単体テストで確認した。

試作段階であり、Windows / Linux / Web、巨大 CSV のメモリ消費、複数ウィンドウ、読み込み途中の失敗、ファイル書き込みエラー、外部変更の競合を含む総合検証は未完了。レガシー外字の対応表、同一形式書き戻し、Unicode / IVS への変換と PDF テキスト抽出も未完了。レセプト等に使う前にはこれらの検証が必要である。
