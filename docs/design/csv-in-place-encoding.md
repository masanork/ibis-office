# CSV / TSV の同一ファイル保存（試作）

元の CSV / TSV の通常保存は、読込時または直前の保存時のバイト列を基準にし、追跡した編集セルだけを置き換える。未編集のフィールド、引用、行ごとの列数、末尾の空欄や改行は再符号化せず元のバイトを保持する。これにより未編集の `00123` や、同じ文字を表す異なる CP932 の符号も保持できる。別名への CSV 出力は従来どおり UTF-8 BOM とし、以後の通常保存ではそのバイト列を基準にする。PDF / OOXML 出力には CSV の文字コードを使わない。

UTF-8（BOM の有無）、UTF-16 LE/BE（BOM 付き）と CP932 を扱う。入力が ASCII のみ、または UTF-8 と CP932 の双方として有効な場合、ネイティブ版では開く際に文字コードを選び、その選択で読み直す。選択中にサイズ・更新時刻が変わった場合は読み込みを中止する。選択肢の Shift_JIS は CP932 であり、厳密な Shift_JIS や独自外字の選択は未対応。選択処理を通らない経路では、判別できない文字コードへの非 ASCII の書き戻しを拒否する。

編集追跡は成功したセル変更・貼り付け・数値書式・書式クリアおよび行・列の挿入／削除・セル移動（`ShiftCells`）の座標・操作履歴を記録し、保存後の undo / redo に加えて保存以前の履歴へ戻る undo / redo（分岐後の再編集を含む）にも対応する。未対応のコマンドや直接モデル変更があると無効になり、取り消しても上書きを拒否する。既存行末尾へのフィールド追加と、最終行の後への行追加はできる。追加行の区切りには元ファイルで最後に使われた行区切りを用い、区切りがない場合は CRLF を使う。最終行の改行の有無は維持する。数式を含め再読込して元の値・数式に戻らないものや、CP932 に正確に表現できない文字は拒否する。同一ファイルへのコピー・書き出しは通常保存を使うよう拒否する。大きな CSV の読込中は、不完全な内容を出力しないよう保存・コピー・書き出し・印刷を拒否する。

保存前に現在のファイルと元バイトを比較し、排他的に作った一時ファイルへ書き込んだ後、置換直前にも再比較する。失敗した場合は追跡や基準バイトを更新しない。シンボリックリンク、読み取り専用ファイル（`readonly()`）、および Unix ではハードリンクのある元ファイルは拒否する。ただし直前の比較と rename の間には競合があり、この方式はファイルシステムの compare-and-swap ではない。保存先のパーミッションは引き継ぐが、ACL や拡張属性の保持は未検証。CSV 保存・読み込みに関するエラーは `CsvInPlaceError` と `shell.tsv`（`en` / `ja`）へ整理した。

macOS の合成データで、実画面から CP932 の CSV を２回編集・保存し、未編集の `00123`、末尾空欄、CRLF と元の文字コードをバイト単位で確認した。アプリのシナリオでも外部変更と表現不能文字の拒否、別名 UTF-8 保存、undo / redo、フィールド・行の追加、行・列の挿入／削除と保存前履歴への undo、パーセント入力、読込中状態を模した出力拒否、および 105,000 行（約 1.37 MB）の CP932 CSV を実アプリで段階的読込（約 1.51 秒）して先頭編集後に上書き保存（約 258 ms）し、読み取り専用・ハードリンク・シンボリックリンクを拒否する動作を確認した。既存の `Kind::Pdf` 分岐漏れ 10 件は独立した修正として `masanork` へ統合済みであり、クリーンなツリーでシナリオテストを実行できる。小さなスタックからの自動判定 CSV 読込、外部変更時とリンク時の書き込み拒否も単体テストで確認した。

試作段階であり、Windows / Linux / Web、巨大 CSV のメモリ消費、複数ウィンドウ、読み込み途中の失敗、ファイル書き込みエラー、外部変更の競合を含む総合検証は未完了。レガシー外字の対応表、同一形式書き戻し、Unicode / IVS への変換と PDF テキスト抽出も未完了。レセプト等に使う前にはこれらの検証が必要である。

保存時のフィールド走査は、編集対象の範囲だけを保持し、文字コードの検証も固定長バッファで行う。100,001 行、約 700 KB の合成 CP932 データで先頭・末尾の編集と不正な末尾の拒否を単体テストした。このテストプロセスの最大 RSS は macOS で約 13 MB だったが、アプリ全体や巨大ファイルのメモリ上限を示す値ではない。元ファイル、現在のディスク内容、出力の全体を保持する経路は残っている。着地条件は [別紙](csv-in-place-landing.md) に整理する。

段階的読込そのものも、100,001 行・約 1.1 MB の合成 CP932 を用い、最初の 100,000 行、最終チャンク、元バイトの保持を単体テストした。macOS のテストプロセス全体では最大 RSS 約 111 MB、実時間 0.31 秒だった。実アプリや複数サイズでの測定、読込中に UI から保存を試す検証ではない。

CSV を含む `ibis-pptx` ライブラリは、macOS ホストから Linux x86_64、Windows x86_64、wasm32 向けの `cargo check` を通過した。アプリ全体のビルドや、各 OS・ブラウザー上での保存動作の検証ではない。

同じホストからのアプリ全体のクロスチェックは、Linux 向け `x86_64-linux-gnu-gcc` と Windows リソースコンパイラ `llvm-rc` がそれぞれ利用できず完了しなかった。各 OS の CI ビルドや実機確認が必要。
