## 配布用の異体字クラスタ

デスクトップ版と Web 版は、Unicode 15.0.0 の [UnicodeData.txt](https://www.unicode.org/Public/15.0.0/ucd/UnicodeData.txt)
から、正準分解先がある CJK 互換漢字だけを取り出した辞書を既定で組み込む。
互換漢字を分解先ごとにまとめ、同じクラスタに属する別の表記を氏名照合で曖昧一致として返す。
たとえば「塚」と「塚」は対象。正準分解で対応づけられていない「髙」と「高」はこの辞書の対象外。
辞書は 1,904 文字、902 クラスタ、圧縮後 10,879 バイト。
Unicode-3.0 のライセンス表示は `crates/ibis-doc-model/UNICODE-LICENSE.txt` と配布物のライセンス一覧に掲載する。

生成方法は `python3 scripts/generate-variant-bitmap.py --unicode-data UnicodeData.txt crates/ibis-doc-model/resources/unicode-15.0-cjk-variants.zst`。
出典の SHA-256 は `806e9aed65037197f1ec85e12be6e8cd870fc5608b4de0fffd990f689f376a73`、
生成物の SHA-256 は `108c4b71ac0b738859b9ab182f8db7e1d9cc9efc5e6a468461c49eb589ee4960`。

## 異体字クラスタのローカル試作

異体字クラスターマップの調製: Masanori Kusunoki (gjs)。この試作は gjs のローカル DB から出力したクラスタ一覧を使うが、DB の元データの版と全出典は固定・確認できていない。gjs の [Third-Party Notices](https://github.com/digital-go-jp/gjs/blob/main/NOTICE.md) はデータと生成物をコードの MIT ライセンスとは別に扱い、MJ文字情報一覧表には CC BY-SA 2.1 JP を挙げている。クラスタへの各データの寄与・条件を検証するまで、このスナップショットやそれを含む成果物を再配布しない。調製者のクレジットは第三者の条件に代わらない。

`python3 scripts/generate-variant-bitmap.py /path/to/clusters_direct.csv /path/to/clusters.zst` でビットマップを生成し、`IBIS_VARIANT_BITMAP=/path/to/clusters.zst` を指定してビルドする。省略時は配布用の Unicode 辞書を使う。辞書が破損して読み込めない場合は画面にその旨を示す。実行時に gjs・soroe やネットワークは不要。ビルド時の環境変数・ファイルはローカル専用であり、配布用辞書の決定を意味しない。

候補はセルを変更しない。クラスタ所属は元資料の直接の関係、同一人物、または置換の安全性を保証しない。文字と異体字セレクタを組み合わせたシーケンスは対象外。大量の結果は先頭200件までとし、その旨を示す。

今回のローカル検証に使った `clusters_direct.csv` は SHA-256 `cf38af4da41ca5daa49d8e556d3e27ed94c9074e6b14d23ca6c67bc8dfef1293`、生成辞書は `544b80b5ba1aeb0c30bccee327379dac244d0aba54b7dc6174061c63ba3187e8`。34,509文字、9,538クラスタ。このハッシュは観測したスナップショットの識別であり、元データの来歴や再配布条件を証明しない。

### 選択範囲の異体字照合

選択された文字列セルを、文字ごとのクラスタ番号を使ってグループ化し、異なる表記が複数ある組だけを候補として読み取り専用で示す。未登録文字はそのまま比較し、大文字小文字、空白、記号、仮名、日付、住所などは別途正規化しない。同じクラスタの所属は直接の対応関係や同一人物を意味しない。異体字セレクタを含む文字列と4096文字を超える文字列は比較から除外して件数を示す。セルは最大10万、合計100万文字、表示は最大200組・各組20表記、各表記のセル番地は10件まで。後続の候補が存在するときは省略を表示する。

表示用フォントの調達・登録は別途検証する。手元の固定クラスタ34,509文字の cmap 調査では、IPAmj＋行政事務標準文字で26,962文字を収録し、gjs の BunsenMinchoExt を追加すると未収録は7文字となった。これは字形やブラウザー表示を検証した数字ではない。フォント条件・登録方法はそれぞれ確認し、未検証のフォントをこの辞書やアプリに同梱しない。

日付レビューペインでは変換候補をプレビューし、確認後に選択範囲へ一括反映できる。異体字レビューペインは選択範囲内の異なる表記をグループ化し、比較先の列を指定せずに候補を探せる。以下の照合関数は、対になる値を比較し、要確認の行や項目を抽出するために使う。

## 属性の照合関数

`=IBIS.FIELDMATCH(A2,B2,"address")` で2つの値を比較する。対応する種類は
`"address"`、`"date"`、`"gender"`、`"name"`、`"kana"`、`"name-with-kana"`、`"phone"`、`"postal"`、`"email"`、`"corporate-number"`、`"mynumber"`、`"drivers-license"`、`"passport-jp"`。セルの値はそのまま保持する。

| 結果 | 意味 |
| --- | --- |
| 2 | 対応する表記をそろえた結果が一致 |
| 1 | 日付の範囲が重なる、2桁年の推定を含む日付が一致、または氏名・振り仮名・住所などが曖昧一致 |
| 0 | 指定した種類の比較で一致が見つからない |
| `#N/A` | 空欄、未対応の値、無効な日付などで比較できない |

候補だけを拾う場合は `=IFNA(IBIS.FIELDMATCH(A2,B2,"date")>0,FALSE)` を使う。
各結果が示すのは属性の一致度であり、同一人物の確定には別の根拠が必要になる。

- 住所では全角数字と全角ハイフンをそろえる。末尾の `二丁目１番２号` と
  `2-1-2` のような三要素の形式を照合し、地名や部屋番号を保持する。建物名などが
  後続する場合、番地形式の変換は行わない。町字辞書や郵便番号は使わない。
  地名部分の「ヶ／ケ／ヵ／が」、「大字・字」の省略、自治体名に先行する一部の島名の省略は曖昧一致とする。
  地名の1文字分の既定ワイルドカードは次のとおり。
  - 文字コード変換の代替符号は U+FFFD（�）と旧来の U+001A（SUB）。[Unicode コード表](https://www.unicode.org/charts/PDF/UFFF0.pdf)
  - 住基ネット由来のデータを含む旧来システムの変換で使われる代替記号は U+25CF（●）と U+3013（〓）。[日本語文字コード入門、61ページ](https://masanork.github.io/mjq/moji20250523.pdf#page=61)
  - 住所照合で扱うその他の伏字は U+25A0（■）、U+003F（?）、U+FF1F（？）。

  JPKI の署名用電子証明書は代替文字を使った住所の位置を別フィールドで伝える。[J-LIS 証明書プロファイル](https://www.j-lis.go.jp/file.jsp?%2Ffile%2F13_profile_genkou.pdf=)
  両方に共通する地名の文字が必要で、番地以降は比較に残す。
  住基ネットでは、統一文字に含まれない外字を識別する符号の一つに `U+D700` の表記を使う。[政府答弁書](https://www.sangiin.go.jp/japanese/joho1/kousei/syuisyo/217/touh/t217184.htm)
  同じ値の Unicode 文字はハングルの「휀」で、既定の照合では通常の文字として比較する。[Unicode Hangul Syllables](https://www.unicode.org/charts/PDF/UAC00.pdf)
  住基由来のエクスポートでこの符号が Unicode 文字として残っていると確認できる場合は、第4引数に
  `UNICHAR(55040)` を渡すと、その文字を1文字分のワイルドカードとして比較する。
  住所は `=IBIS.FIELDMATCH(A2,B2,"address",UNICHAR(55040))`、氏名は
  `=IBIS.FIELDMATCH(A2,B2,"name",UNICHAR(55040))`。ほかの外字も、対象文字を並べたセルを第4引数に指定できる。
- 日付は西暦、和暦、ブックの日付システムに従う整数のシリアル値を扱う。年月や年だけの
  入力は改元日で範囲を区切る。2桁年は既存の日付レビューと同じ境界を使う。
- 性別は `男／男性／M／Male` と `女／女性／F／Female` の表記を扱う。数値コードや
  不明は比較対象外にする。
- XLSX には ibisOffice 独自関数として保存する。Excel での再計算との互換性はない。

### 複数項目の照合

`=IBIS.RECORDMATCH(E2,F2,G2)` は、氏名・生年月日・住所などを比較した各項目の結果をまとめる。

- 1項目でも不一致（0）があれば 0。
- 全項目が一致（2）なら 2。
- 不一致がなく、曖昧一致（1）や比較不可（`#N/A`、空欄）があり、比較できた項目があれば 1。
- 全項目が比較不可なら `#N/A`。その他の数式エラーはそのまま返す。

項目の重み付けは行わない。必須項目を別条件で絞る場合は、個別の照合結果も条件に含める。
`=IF(IFNA(IBIS.RECORDMATCH(E2,F2,G2)=1,FALSE),"要確認","")` で候補行に印を付けられる。

1つの範囲を渡すと、横に並ぶ項目をまとめて各行に対して1つの判定を返す。
`=IBIS.RECORDMATCH(E2:G100)` の結果は縦方向にスピルする。
`=FILTER(A2:D100,IFNA(IBIS.RECORDMATCH(E2:G100)=1,FALSE),"候補なし")` で
要確認の行だけを取り出せる。複数の引数を渡した場合は、引き続き同じ位置どうしを比較する。

### 氏名の比較

`=IBIS.FIELDMATCH(A2,B2,"name")` で氏名を比較する。
空白をそろえた一致は 2。伏字や外字、組み込み済みの異体字クラスタ、旧姓併記による一致は 1。
住所と同じ既定の伏字を使い、追加の外字は第4引数で指定できる。
配布用の異体字クラスタを既定で使う。ローカルビルドでは `IBIS_VARIANT_BITMAP` で別の辞書に差し替えられる。

`田中（旧姓：山田）花子`、`田中・旧姓山田 花子` のように旧姓が明記されていれば、
現姓と旧姓の両方を照合する。双方が姓と名を空白で区切っている場合、名が一致して姓が違う組も
候補として 1 を返す。区切りのない氏名の姓・名は辞書なしで推定しない。
旧姓の明記がある場合も、名前だけから同一人物を確定する用途には使わない。

### 振り仮名の比較

`=IBIS.FIELDMATCH(A2,B2,"kana")` は入力済みの読みを比較する。
ひらがな・カタカナ、全半角カナ、結合された濁点・半濁点、空白の違いを吸収して一致すれば 2。
長音表記だけが異なる場合（例「オオノ」と「オーノ」）は 1。
小書きの仮名、濁音、中点の有無などの相違は 0。空欄や漢字を含む値は `#N/A`。
読みの辞書による推定は行わない。

`=IBIS.FIELDMATCH(A2,B2,"name-with-kana",C2,D2)` は氏名と各人の読みを合わせて確認する。
氏名と読みが両方とも一致すれば 2。氏名または読みが不一致なら 0。
不一致がなく、曖昧一致や読みの空欄があれば 1。氏名が空欄、または記入された読みが比較できない場合は `#N/A`。
このモードの第4・第5引数は左と右の読み。氏名の伏字には既定の文字を使う。

### 電話番号と郵便番号

- `=IBIS.FIELDMATCH(A2,B2,"phone")` は電話番号の文字列を比較する。
  全半角・空白・ハイフン・括弧の差を吸収し、日本の国内番号と `+81` の形式を照合する。
  本体と内線が一致すれば 2、同じ本体で片側にだけ内線があれば 1、異なる本体や内線は 0。
  市外局番や先頭ゼロなど、番号の欠けた文字列と数値セルは比較対象外。
  国際番号は `+` で始まる形式を扱い、番号の割り当てや有効性は確認しない。
- `=IBIS.FIELDMATCH(A2,B2,"postal")` は日本の7桁の郵便番号を比較する。
  〒、数字の全半角、3桁と4桁の間のハイフンや空白の違いを吸収する。
  5〜6桁の数値セルは、もう一方の完全な7桁と先頭ゼロを補って一致する場合に 1。
  短い文字列や双方が5〜6桁の数値なら `#N/A`。町域との対応は確認しない。

### メールアドレスと識別番号

- `=IBIS.FIELDMATCH(A2,B2,"email")` は前後の空白を除き、ドメインの大小文字をそろえる。
  ユーザー部の大小文字、ピリオド、プラスタグは比較に残す。
  通常の ASCII メールボックス形式を対象にし、引用符付きのユーザー部や Unicode アドレスは `#N/A`。
  [RFC 5321 §2.4](https://datatracker.ietf.org/doc/html/rfc5321#section-2.4)
- `=IBIS.FIELDMATCH(A2,B2,"corporate-number")` は日本の法人番号を比較する。
  13桁の整数セルを受け付け、文字列セルでは全角数字・空白・ハイフンの差を吸収する。
  検査用数字が合わない場合は `#N/A`。形式と検査用数字を確認できた値について、
  一致は 2、不一致は 0 を返す。番号の割り当てや法人の現況は照会しない。
  [国税庁の検査用数字の算式](https://www.houjin-bangou.nta.go.jp/documents/bangouhou_syorei.pdf)
- `=IBIS.FIELDMATCH(A2,B2,"mynumber")` は12桁の個人番号の検査用数字を確認して比較する。
  全角数字・空白・ハイフンの差を吸収し、先頭にゼロがある場合は文字列セルで保持する。
  検証した番号同士が一致すれば 2、相違すれば 0。短い値や検査用数字が合わない値は `#N/A`。
  個人番号の割り当ては照会しない。
  [検査用数字の算式（e-Gov 法令検索）](https://laws.e-gov.go.jp/law/426M60000008085/20260526_508M60004008006)
- `=IBIS.FIELDMATCH(A2,B2,"drivers-license")` は日本の12桁の運転免許証番号を比較する。
  全角数字・空白・ハイフンの差を吸収し、先頭10桁から11桁目の検査桁を確認する。
  両方の検査桁が確認でき、12桁目の再交付記号だけが異なる場合は 1 を返す。
  検査桁は、重み付き合計を11で割った余りを11から引き、その下一桁を使う。
  [警察庁通達](https://www.npa.go.jp/laws/notification/menkyo20250310_76.pdf)
  [重みの計算例（公開特許公報）](https://patents.google.com/patent/JP2013109736A/ja)
  [下一桁の扱い（実測に基づく計算例）](https://tetsutalow.github.io/driversnumbercheckdigit/)

- `=IBIS.FIELDMATCH(A2,B2,"passport-jp")` は英字2文字・数字7桁の日本の旅券番号を比較する。
  全半角、英字の大小文字、空白、ハイフンをそろえる。形式を満たす値が一致すれば 2、相違すれば 0。
  形式外の値は `#N/A`。英字1文字の形は対象外。
  番号の真正性・有効性は照会しない。更新後は番号が変わるため、同じ旅券の番号を照合する用途に使う。
  [埼玉県パスポートセンターの券面説明](https://www.pref.saitama.lg.jp/passport/juryo/mikata.html)
  [外務省の更新時の番号に関する説明](https://www.mofa.go.jp/mofaj/ca/pss/page23_003544.html)
  日本旅券の TD3 MRZ は2行ともセルに入っていれば比較できる。各行44文字、上段の発行国 `JPN`、
  下段の旅券番号とその直後の検査桁を確認して番号を取り出す。下段の国籍欄は発行国の代用にしない。
  生年月日・有効期限・任意データの検査桁と、下段の総合検査桁も確認する。任意データ欄が空の場合は検査桁の 0 とフィラーの両方を受け付ける。\n  総合検査桁の対象は下段の 1〜10、14〜20、22〜43 桁。氏名、国籍、性別はその対象に含まれない。
  [ICAO Doc 9303 Part 4（フィールド位置）](https://www.icao.int/sites/default/files/publications/DocSeries/9303_p4_cons_en.pdf)
  [Part 3（検査桁の算式）](https://www.icao.int/publications/documents/9303_p3_cons_en.pdf)
