# CSV 同一ファイル保存: masanork 着地条件

この試作は、既存 CSV の未編集フィールドのバイトを保ちながら、元の文字コードで上書きするためのもの。`masanork` の通常機能として有効化する前に、以下を満たす。実装・検証の現状は [CSV / TSV の同一ファイル保存](csv-in-place-encoding.md) を参照。

1. **通常編集の互換性**: 保存後の追跡可能なセル編集の undo / redo、既存行末尾へのフィールド追加、最終行の後への行追加と、再読込で一致する数式の保存は試作済み。保存以前の履歴、行・列やセルの挿入・削除、複雑な数式、書式付き数値を含む操作の意図を保持する。対応できない操作は上書き前に説明し、別名保存で何が変わるか明確にする。未編集フィールド・引用・改行・空欄・CP932 の重複符号を維持し、保存後の再読込と複数回保存を検証する。
2. **大きなファイル**: 先頭だけ読んだ状態で保存・コピー・印刷・変換できないことを実際の段階的読込で確認する。複数サイズ・列数・編集密度で読込と保存の時間および最大メモリを測る。編集対象以外の位置情報や全デコード文字列の追加確保を避ける。元バイト、現在のファイル、出力全体の保持・再読込はなお残るため、上限と失敗時の挙動を決める。
3. **ファイルシステムと競合**: macOS、Windows、Linux それぞれで上書き成功・権限不足・容量不足・外部更新・別ウィンドウを試す。シンボリックリンク、ハードリンク、ACL、拡張属性を検証し、保持できない場合の扱いを決める。現在の最終比較と rename の間には競合があり、完全な競合防止ではない。
4. **文字コードと UI**: UTF-8 の BOM 有無、UTF-16 LE / BE、CP932、ASCII と UTF-8 / CP932 が曖昧な入力について、選択・キャンセル・読直し・別名保存・失敗時の通知を検証する。エラーを各言語へ揃え、ASCII ファイルにも選択が現れることの操作性を評価する。ブラウザー版とネイティブ版の差を明記する。
5. **統合と最終検証**: 最新 `masanork/masanork` を再取得し、他の worktree の未コミット変更を保持したまま統合する。最終統合 head で必要なテストと CI を確認し、GUI 検証と CI の証拠範囲を区別する。現状のアプリシナリオには既存の PDF 分岐漏れがあり、試作での一時補正ではクリーンなツリーでの実行を代替できない。

PUP / 住基文字から Unicode・IVS への変換と PDF のテキスト抽出は別の作業として評価し、この CSV 保存の完成をそれらの完成と取り違えない。
