# CSV 同一ファイル保存: masanork 着地条件

この試作は、既存 CSV の未編集フィールドのバイトを保ちながら、元の文字コードで上書きするためのもの。`masanork` の通常機能として有効化する前に、以下を満たす。実装・検証の現状は [CSV / TSV の同一ファイル保存](csv-in-place-encoding.md) を参照。

1. **通常編集の互換性**: 保存後の追跡可能なセル編集の undo / redo、保存以前の履歴への undo / redo（分岐後の再編集を含む）、行・列やセルの挿入・削除（`Insert` / `Delete` / `ShiftCells`）、貼り付け（`PutCells`）、数値書式変更・書式クリア、既存行末尾へのフィールド追加、最終行の後への行追加と、再読込で一致する数式の保存を実装・単体／シナリオ検証済み。未編集フィールド・引用・改行・空欄・CP932 の重複符号を維持し、保存後の再読込と複数回保存を検証した。複雑な数式・独自書式等で対応できない場合は上書き前に拒否する。
2. **大きなファイル**: 105,000 行（約 1.37 MB）の CP932 CSV で実アプリの段階的読込（約 1.51 秒）と上書き保存（約 258 ms）をシナリオ検証済み。さらに巨大なサイズ・列数・高編集密度での最大メモリ測定と上限・失敗時挙動の定義が残る。
3. **ファイルシステムと競合**: macOS では上書き成功・読み取り専用拒否・外部更新拒否・シンボリックリンク／ハードリンク拒否をシナリオ検証済み。Windows・Linux での実機動作、複数ウィンドウ、ACL・拡張属性の保持、および最終比較と rename の間の競合防止は未完了。
4. **文字コードと UI**: CSV 関連エラーを `CsvInPlaceError` と `shell.tsv`（`en` / `ja`）へ多言語化し、ブラウザー版（WASM）とネイティブ版の差（ブラウザー版はローカルファイル上書きを行わずエクスポート経路のみ）を `csv-in-place-encoding.md` に明記済み。UTF-8 の BOM 有無、UTF-16 LE / BE、CP932、ASCII と UTF-8 / CP932 が曖昧な入力の選択 UI の実機操作性評価が残る。
5. **統合と最終検証**: 既存の `Kind::Pdf` 分岐漏れ 10 件は独立修正として `masanork` へ統合済みで、クリーンなツリーでシナリオテストを実行可能。最終統合 head で必要なテストと CI を確認し、GUI 検証と CI の証拠範囲を区別する。

PUP / 住基文字から Unicode・IVS への変換と PDF のテキスト抽出は別の作業として評価し、この CSV 保存の完成をそれらの完成と取り違えない。
