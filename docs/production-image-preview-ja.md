# 制作素材のプレビュー

ibisOffice のフォークでは、制作・放送アーカイブ用の画像をファイルから直接開けます。受け取った素材の絵柄、透明度、連番の欠けを確認し、必要に応じて確認用の Word 文書にできます。

## ファイルを開く

デスクトップ版またはブラウザー版で、通常の文書と同じ「ファイル」→「開く」から画像を選ぶと、ページ上にプレビューが表示されます。拡張子が同じでも、ファイルの格納方式や色空間によっては開けないことがあります。

| 形式 | 拡張子 | 開ける素材と表示方法 |
| --- | --- | --- |
| TGA | `.tga` | RLE圧縮を含む画像。画像の向きとアルファを反映します。 |
| JPEG / PNG | `.jpg`、`.jpeg`、`.png` | 静止画。PNGのアルファを保持します。 |
| TIFF | `.tif`、`.tiff` | 複数画像を収録したTIFFは先頭画像を表示します。 |
| Photoshop | `.psd` | 8ビットRGBの保存済み合成画像。合成画像がない場合は、Photoshopの互換性を最大化する設定で保存し直してください。 |
| HEIC / HEIF | `.heic`、`.heif` | HEVCで符号化した静止画の主画像。ブラウザー内蔵デコーダーで開けない場合はソフトウェアデコーダーに切り替えます。 |
| OpenEXR | `.exr` | 単一パートの非Deep画像。シーンリニアRec.709のRGB/RGBAをSDR表示に変換します。色情報の記載がない場合はRec.709として扱います。 |
| DPX | `.dpx` | 非圧縮・符号なし・充填方式A/Bの10ビットRGBを1要素含む画像。リニアまたはビデオのRec.709をsRGBに変換します。 |
| Cineon | `.cin` | 画素単位でRGBを格納した符号なし10ビットの正極性スキャン。Kodakの標準黒白点を使ってSDR表示に変換します。 |
| JPEG 2000 | `.jp2`、`.j2k`、`.j2c` | JP2コンテナーと生のJ2K/J2Cを開きます。色変換と符号化方式の対応範囲は下記のとおりです。 |

## 素材を確認する

- **透過と背景**　画像を開いた状態で、ステータスバーの「ページ背景」をクリックすると、市松模様、黒背景、アルファチャンネルの順に切り替わります。アルファチャンネル表示では黒が完全透明、白が不透明です。
- **OpenEXRの露出**　ステータスバーの − / ＋ で露出を調整し、EV値をクリックすると0 EVに戻ります。変化を見ながら暗部や明部を確認できます。
- **連番のコマ送り（デスクトップ版）**　同じフォルダーにある同一接頭辞・同一桁数・同一拡張子のファイルを連番として扱います。`shot.0001.exr` と `shot.0003.exr` がある場合、ステータスバーの「次のコマ」で `0003` に進み、欠番を1コマ飛ばしたことが表示されます。
- **確認用DOCX**　元の素材を残したまま、プレビュー画像を別のDOCXに保存できます。背景やアルファ表示、OpenEXRの露出調整は表示用です。保存される画像は取り込み時のプレビューで、透明度を保持します。ブラウザー版を埋め込んだ場合も、画像からのダウンロードは `素材名.docx` です。[ブラウザー版の組み込み](web-embedding-ja.md)

## 原本の来歴

JPEG・PNG・TIFFを開き、ステータスバーの「素材の来歴」を選ぶと、原本に埋め込まれたC2PAの検証結果を確認できます。原本とマニフェストの整合性、署名証明書の信頼、記録された操作や元素材が表示されます。署名証明書の信頼は、記録内容の事実確認とは別です。

Web版も原本のバイト列に対してブラウザー内でC2PAを検証します。両本番ドメインのChromeで、信頼済み、署名者の信頼未確認、原本とのハッシュ不一致、マニフェスト未検出、外部マニフェスト未取得の5状態を確認しました。署名付きPNGをローカルファイルとして開き、保存したDOCXの全RGBA画素が原本と一致し、C2PAマニフェストを含まないことも確認しました。検証中に素材のアップロードや外部マニフェストへの通信は発生しませんでした。検証時の配信元は `fca01b25` です。

検証には同梱のC2PA信頼リストとタイムスタンプ局の信頼リストを使います。外部マニフェストの取得と失効状況のオンライン照会は行いません。確認用DOCXの作成は検証とは独立しており、原本のC2PAマニフェストをDOCXには付与しません。信頼リストはアプリ更新で配布します。[信頼リストの出所と更新手順](../crates/ibis-office-shell/data/c2pa/README.md)

macOS（Apple Silicon）のローカル検証版では、公式リストで信頼される署名付きPNG、署名者の信頼を確認できないテストJPEG、原本とのハッシュ不一致、マニフェスト未検出のTIFF、外部マニフェストを参照するJPEGを開き、表示を確認しました。Cineonに切り替えると前の素材の来歴表示は消えます。署名付きPNGから保存したDOCXでは、全RGBA画素が原本と一致し、C2PAマニフェストは含まれていませんでした。[署名付きPNGの公開サンプル](https://c2paview.com/samples/enoggera-creek.png) [外部マニフェストの公開サンプル](https://contentauth.github.io/example-assets/images/crater-lake-cr.jpg)

合成画像と専用のテスト証明書を使った自動回帰テスト、保存後の来歴表示、サイズ・処理時間の計測方法は [C2PA検証の受け入れ確認](c2pa-verification.md) を参照してください。

## JPEG 2000の色と互換性

- グレーおよびRGB系の画像を8ビット表示用に変換します。埋め込みのRGB・CMYK ICCプロファイルはsRGBに変換し、対応するストレートアルファは保持します。
- タイルパートのPOC（パケット順序の変更）は、全レイヤー・全成分を対象とし、解像度の上限がタイルパートごとに増える方式に対応しています。OpenJPEGの標準適合性テスト素材 `p0_07.j2k` を両本番ドメインのChromeで開き、DOCX内の全RGB成分が8ビットに正規化した参照結果と一致することを確認しました。
- 各タイルパートにはLRCP、RLCP、RPCL、PCRL、CPRLの5方式を指定できます。本番Webでは5方式に加え、途中でRLCPからCPRLに切り替わる試験画像もChromeで開き、DOCX内のRGB成分がOpenJPEGの参照結果と一致しました。
- 可逆変換のMaxshift ROIにも対応しています。両本番ドメインのChromeで `p0_03.j2k` を開き、DOCX内の全65,536グレー画素がOpenJPEGの参照結果と一致することを確認しました。
- メインヘッダーの単一POCで全パケットを覆う場合は、LRCP、RLCP、RPCL、PCRL、CPRLの5方式を扱えます。OpenJPEGで生成した4タイル・2品質レイヤーの試験画像を両本番ドメインのChromeで開き、5方式すべてでDOCX内のRGB成分が参照結果と一致しました。
- メインヘッダーの1つのPOCマーカーに複数の範囲を記述し、全レイヤー・全成分を対象に解像度の上限を順に広げながらパケット順序を切り替えられます。両本番ドメインのChromeで、各タイルが1個または2個のタイルパートを持つ試験画像を開き、DOCX内のRGB成分がOpenJPEGの参照結果と一致しました。
- メインヘッダーとタイルパートのPOCで開始解像度を明示する構成にも対応しています。対応する範囲は全レイヤー・全成分を含み、解像度に欠けがないものです。両本番ドメインのChromeで、メインヘッダーのPOCで各タイルを1個または2個のタイルパートに分けた構成と、タイルパートにPOCを置いた構成の計3件を開き、DOCX内の全RGB成分がOpenJPEGの参照結果と一致しました。
- OpenJPEGの公開素材で読み込みや表示値を検証しています。実際の放送アーカイブ素材は未検証です。独自テロップ形式とHDR出力は未対応です。[OpenJPEGの公開検証素材](https://github.com/uclouvain/openjpeg-data/tree/39524bd3a601d90ed8e0177559400d23945f96a9/input)
