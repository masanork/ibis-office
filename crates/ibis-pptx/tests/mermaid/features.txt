# Mermaid syntax features tracked by the corpus test (tests/mermaid_corpus.rs).
#
# Each line: doc | feature | status | match | pattern
#   doc     corpus file stem, or * for every supported document
#   status  ok      = drawn by ibis-pptx
#           gap     = parsed past or ignored; the diagram renders without it
#           wontfix = deliberately not supported (scripts, links)
#   match   prefix   a trimmed body line starts with the pattern
#           contains a body line contains the pattern
#           front    a top-level YAML frontmatter key starts with the pattern
#           header   the diagram header line contains the pattern
#           config   a frontmatter `config:` leaf, as a dotted path below `config`, starts with the
#                    pattern (`gitGraph.showBranches`, `themeVariables.git0`); `*` matches a case
#                    with any config leaf that no other `config` line for its document covers;
#                    a trailing `$` matches the whole key only (`theme$` is not `themeVariables.*`)
# A feature may have several lines (any of them matches). A case is "clean" when it renders and
# uses no `gap` feature. The heuristics are deliberately simple; they rank work, they do not prove it.
